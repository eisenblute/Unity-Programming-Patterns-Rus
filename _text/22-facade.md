# 22. Фасад (Facade)

Используется, когда у вас есть несколько связанных классов (например, для ИИ или аудио) и вы хотите упростить доступ к методам в этих классах. Название «Фасад» происходит от [архитектурного фасада](https://en.wikipedia.org/wiki/Fa%C3%A7ade) — вы видите только внешнюю сторону здания, но понятия не имеете, как оно выглядит внутри. При необходимости вы всё ещё можете обращаться к классам подсистемы напрямую — фасад лишь упрощает доступ к наиболее часто используемым классам.

**Как это реализовать?**

Создайте класс-менеджер, который предоставляет единый интерфейс к большой коллекции связанных классов.

**Когда это полезно?**

- В играх часто пишут стандартизированные библиотеки кода — например, библиотеку для ИИ, включающую поиск пути и т.д. Такие библиотеки обычно содержат огромное количество классов. Чтобы упростить себе жизнь, вы создаёте скрипт, который предоставляет доступ к самым важным методам (например, «получить короткий путь»). Я сделал библиотеку с открытым исходным кодом: [Computational geometry](https://github.com/Habrador/Computational-geometry). В ней есть несколько методов для генерации триангуляции Делоне. Чтобы упростить доступ к этим методам, я написал класс `_Delaunay`, который обращается к каждому методу Делоне простым способом. Без этого вам пришлось бы сначала зайти в папку Delaunay и выяснить, какой класс что делает и какой метод следует использовать для получения нужной триангуляции. Если бы я решил использовать другую библиотеку триангуляции, мне нужно было бы изменить только скрипт фасада. Допускается использование нескольких фасадов, поэтому у меня есть ещё один фасад для алгоритмов пересечения (intersection).
- Случайные числа часто используются в играх. Что стоит использовать: `Random.Range` из Unity или `System.Random.Next` из C#? Вы можете использовать паттерн «Фасад», чтобы легко переключаться между ними. Пример этого можно найти в исходниках. А если позже вы найдёте третью библиотеку для генерации случайных чисел, то сможете добавить и её, при этом вам не придётся вносить ни одного изменения в код, который использует этот фасад.
- Может упростить взаимодействие с аудио, предоставляя методы для воспроизведения, паузы, остановки и управления различными источниками звука.
- Может предоставить унифицированный интерфейс для обработки ввода с клавиатуры, мыши и контроллера, скрывая сложности, связанные с разными устройствами ввода.
- Может использоваться для создания упрощённого интерфейса для операций сохранения и загрузки игры. Он инкапсулирует детали сериализации, десериализации и хранения данных.
- Для игр с симуляцией физики фасад может предоставлять упрощённый интерфейс для приложения сил, обнаружения столкновений и управления физическими взаимодействиями, скрывая сложности низкоуровневого физического движка.

**Связанные паттерны**

- **Поиск службы (Service Locator).** Локатор служб не обязательно состоит из нескольких классов — нужная нам служба может быть представлена одним классом. Но «Поиск службы» может использовать паттерн «Фасад».
- **Синглтон (Singleton).** Класс-фасад часто является синглтоном, потому что вам нужен только один объект для управления доступом к аудио или к ИИ.
- **Адаптер (Adapter).** Этот паттерн занимается тем, что заставляет работать с вашей системой код, который вы не можете изменить. В то время как «Фасад» создаёт новый интерфейс для упрощения, «Адаптер» адаптирует старый интерфейс. Эти паттерны настолько похожи, что в одной книге они были включены в одну и ту же главу.
