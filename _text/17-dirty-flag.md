# 17. Грязный флаг (Dirty Flag)

Этот паттерн полезен, если в вашей игре что-то изменилось, и в ответ на это нужно выполнить какую-то ресурсоёмкую операцию. «Грязный флаг» используется, чтобы указать, что что-то изменилось, но сама "тяжёлая" операция ещё не была запущена. Часто можно отложить эту операцию до того момента, когда её результат действительно понадобится. Таким образом, этот паттерн позволяет играм избегать ненужных вычислений, обновлений и обработки данных.

**Как это реализовать?**

«Грязный флаг» — это просто переменная типа `bool` (логическое значение: истина / ложь).

**Когда это полезно?**

- **Сохранение игры** может быть ресурсоёмкой операцией. Если в игре что-то изменилось и это изменение тоже нужно сохранить, вы устанавливаете «грязный флаг» в объекте сохранения игры в значение `true`. Теперь, если игрок захочет выйти из игры, вы можете легко сообщить ему, что есть несохранённые изменения. Пример этого можно найти в исходниках.
- **При создании редакторских скриптов для Unity** вы можете использовать метод `SetDirty()`, чтобы пометить объект как «грязный», или даже пометить всю сцену как «грязную». Теперь Unity будет знать, что вы что-то изменили, и эти изменения должны быть сохранены, когда вы сохраните сцену.
- **Unity использует этот паттерн в физической системе.** Объект с `RigidBody` не нужно обновлять, если к нему не была приложена сила. Если `RigidBody` «спит» (не двигается), используется «грязный флаг», чтобы физическая система могла его игнорировать.
- **Я использовал этот паттерн, когда экспериментировал с генетическими алгоритмами (GA) и задачей коммивояжёра (TSP)** — поиск кратчайшего пути между несколькими городами. Генетический алгоритм генерирует множество решений (например, 100) для задачи TSP, а затем на каждой итерации мы получаем 100 лучших решений, вычисляя *функцию стоимости* (cost function), которой в данном случае является расстояние между всеми городами. Можно использовать «турнирный отбор» (tournament selection) для перехода от предыдущей итерации к следующей — это когда вы выбираете 3 решения и возвращаете то из них, у которого расстояние между городами наименьшее. Я понял, что мне не нужно вычислять функцию стоимости 100 раз на каждой итерации, потому что это "дорогая" операция. Для оптимизации я вычислял функцию стоимости только для тех городов, которые были выбраны турнирным отбором. Я отслеживал, для какого решения функция стоимости уже вычислена, с помощью `bool`-флага, который сбрасывался в `false` на каждой итерации и устанавливался в `true`, если функция стоимости была запущена.
- **В многопользовательских играх** паттерн «Грязный флаг» можно использовать при отслеживании изменений состояния игры для сетевой синхронизации. Только данные, помеченные как «грязные», нужно отправлять по сети, что снижает использование пропускной способности и улучшает сетевую производительность.
- **Может использоваться для отслеживания изменений в игровом окружении или состоянии ИИ.** Тогда система ИИ может расставлять приоритеты для обновления и принятия решений для объектов или ИИ-агентов с «грязными» данными.
